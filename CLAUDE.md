This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this project does

Renders a GPX route as a 3D curve on a stylized elevation map with contour lines inside Blender, then animates a camera following the progressive trace of the route, producing a video. The terrain is black, contour lines are white emission, and the GPX track is red emission.

## Running the scripts

All scripts run inside Blender's Python environment (Text Editor → Run Script), or headless:

```powershell
# Headless (adjust path to your Blender installation)
blender --background --python scripts/blender_animate.py
```

Outside Blender (pure-Python functions only — Blender scene operations are skipped):

```powershell
.venv\Scripts\python scripts/blender_animate.py
```

Running tests:

```powershell
.venv\Scripts\pytest scripts/
```

Convert rendered PNG frames to MP4:

```powershell
.venv\Scripts\python scripts/frames_to_mp4.py
```

## Entry point

### `blender_animate.py` — pipeline + flight plan animation

Hosts the DEM/contour/terrain/GPX pipeline and the flight-plan camera animation. To switch to a new GPX, only change `GPX_NAME` near the top — everything else (DEM folder, terrain/contour/material params) is meant to stay stable across routes.

The camera plan itself is **not** defined inline. `load_flight_plan(GPX_NAME)` imports `flight_plans/<GPX_NAME>.py` and reads its module-level `PLAN`, so route-specific camera tuning never touches this shared pipeline script. To add a new route:

1. Copy `flight_plans/_template.py` to `flight_plans/<GPX_NAME>.py`.
2. Edit its `PLAN` (steps, distances, smoothing) for that route.
3. Set `GPX_NAME` in `blender_animate.py` to match.

```python
# flight_plans/<GPX_NAME>.py
from flight_plan import FlightPlan, Start, ForwardFollow, BackwardFollow, Rotate

PLAN = FlightPlan(
    steps=[
        Start(end_t=0.0,  azimuth=140.0, elevation=25.0, distance=5000.0),
        ForwardFollow(end_t=0.5,  distance=3000.0, height=500.0),
        Rotate(end_t=0.62, end_azimuth=235.0, end_elevation=30.0, distance=3000.0),
        BackwardFollow(end_t=1.0, distance=3000.0, height=500.0),
    ],
    smoothing=0.05,
)
```

Set `RENDER_PREVIEW = True` first to render 3 PNGs per step (fast) and tune parameters. Then set `RENDER_PREVIEW = False` for the full animation. Missing a `flight_plans/<GPX_NAME>.py` file raises a `FileNotFoundError` with the expected path.

## Flight plan architecture

`flight_plan.py` and `gpx_trace.py` are **pure Python with no Blender dependency** — they can be unit-tested outside Blender.

### GPXTrace (`gpx_trace.py`)

Wraps the list of Blender-projected 3-D points and GPS timestamps. Builds a 1001-sample lookup table at init time mapping animation fraction `t ∈ [0, 1]` to a fractional GPX point index, respecting real elapsed time when timestamps are present. Public API:

- `head_at(t)` — 3-D world position of the trace head
- `travel_dir_at(t)` — normalised horizontal direction of travel (finite difference over a configurable window)
- `bevel_factor_at(t)` — value for `curve.bevel_factor_end` to reveal the trace up to t

### FlightPlan (`flight_plan.py`)

A sequence of `CameraStep` objects. Call `camera_pose(t, gpx_trace)` in ascending `t` order to get EMA-smoothed `CameraPose(position, target)` at each frame.

#### Step types

| Class | Camera position | Looks at |
|-------|----------------|----------|
| `Start` | Fixed spherical offset from head at t=0 | Head |
| `ForwardFollow` | `distance` metres **behind** travel direction, `height` above head | Point `look_ahead` metres ahead of head |
| `BackwardFollow` | `distance` metres **ahead** of travel direction, `height` above head | Head (or `look_behind` metres behind it) |
| `Rotate` | Orbits head at `distance`, sweeping from auto-captured start to `end_azimuth`/`end_elevation` | Head |

#### Smoothing and interpolation

- All steps share a single `smoothing` EMA factor defined on `FlightPlan`. At each frame: `actual = lerp(actual, desired, smoothing)`. Low values (0.03) feel floaty; high values (0.15) feel snappy.
- `Rotate` additionally uses **smootherstep** (Ken Perlin's degree-5 Hermite, zero velocity and acceleration at both ends) for the orbital sweep angle, giving a cinematic ease-in/ease-out independent of the EMA.
- `Rotate` captures its start azimuth/elevation automatically from the EMA position at the moment the step begins — the user only specifies the target.

#### Preview

`plan.preview_poses(gpx_trace)` replays the EMA from `t=0` for each of 3 sample points per step (start, mid, end), returning `(t, step, label, CameraPose)` tuples. `blender_animate.py` renders these as PNGs to `render/flight_preview/`.

### Azimuth convention

Both files use the **standard math convention**: azimuth=0 → +X axis, azimuth=90 → +Y axis (counter-clockwise).

## Pipeline

| Step | Functions (in `blender_animate.py`) | Notes |
|------|-------------------------------------|-------|
| 1. Clean scene | `clean_scene` | Removes terrain/contours/GPX/camera objects |
| 2. Load GPX | `load_gpx` | Returns lon/lat/elev/timestamps via `gpxpy` |
| 3. Select DEM tiles | `gpx_to_dem_coords`, `discover_dem_candidates`, `select_dem_tiles_for_gpx` | WGS-84 → EPSG:2154; selects `.asc` tiles overlapping GPX segments |
| 4. Merge & crop DEM | `merge_dem_tiles`, `crop_dem_to_bounds` | Mosaic → crop to GPX bbox + `DEM_MARGIN` |
| 5. Terrain mesh | `create_terrain` | One vertex per DEM cell; Z = elevation × `VERTICAL_EXAGGERATION` |
| 6. Contour lines | `generate_contour_segments`, `create_contour_object` | Marching squares; cached as `.npz` in `cache/` |
| 7. GPX projection | `project_gpx`, `create_gpx_curve` | Ray-cast onto terrain; curve with `bevel_depth` for render visibility |

## Key technical notes

### Renderable geometry rule

Cycles/EEVEE render **surfaces** only. A Mesh with edges but no faces is invisible in renders. All rendered objects use either mesh faces (terrain) or Curves with `bevel_depth` (GPX track, contour lines).

### Contour cache

`contour_cache_path` hashes DEM paths + GPX path + interval + bounds (SHA-256, 16-char digest). Files live in `cache/`. Any path change produces a new hash; old files are harmless orphans. Delete `cache/` to force full regeneration.

### Blender API compatibility

`bpy` and `mathutils` are wrapped in `try/except` at import. A minimal `Vector` stub enables unit-testing outside Blender. `render_utils.set_bevel_linear` handles both the pre-4.4 `action.fcurves` API and the Blender 4.4+ layered action API (`action.layers[0].strips[0].channelbags[0].fcurves`) when forcing `bevel_factor_end` keyframes to LINEAR interpolation. `render_utils.render_animation` renders via the `FFMPEG` image-settings format and falls back to a `<stem>_frames/frame_*.png` sequence (with the `ffmpeg` command to assemble it) on Blender builds that lack the FFMPEG muxer.

### DEM data

- Source: French IGN RGE Alti, Lambert 93 (EPSG:2154)
- Format: Arc/Info ASCII Grid (`.asc`)
- Location: `contour_lines/isere/ign/`
- CRS detection: `infer_dem_crs` checks for `LAMB93`/`IGN69` in the filename when rasterio cannot read the CRS from the file header
